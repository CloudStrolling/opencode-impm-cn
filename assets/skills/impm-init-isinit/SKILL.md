# impm-init-isinit 技能

## 触发词
- 初始化判定
- 是否已初始化
- 空项目
- 存量项目
- isinit

## 何时使用
- 初始化阶段（/impm-init）的第一步，需要先判定项目初始化状态时。
- 用户询问当前项目是否已初始化、应按空项目还是存量项目处理时。

## 执行角色
本技能由 PM（项目经理，主控 Agent）直接执行，不启动 subagent。

## 调度说明（启动本技能时必须遵守）
1. 本技能不启动 subagent，由 PM 直接执行。
2. 执行上下文：项目根目录绝对路径（projectRoot）；判定结果（空项目/存量项目/已初始化）必须作为上下文传交给后续步骤。
3. 完成要求：isinit 的进度行由 impm-init-version 步骤统一补录，本步骤结束后将判定结论反馈给用户与后续步骤。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文名称 | 项目的英文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接所有文档路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 当前版本号 | 当前执行的版本号（初始化阶段固定为 0.0.1） | 通过 impm_version 获取或从版本目录名推断 |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 只执行本技能规定的操作，不做与任务无关的工作。
3. 所有文档路径必须用 {项目英文缩写} 和 {当前版本号} 拼接，不得臆造文件名。
4. 使用 impm_* 工具获取信息，不得编造工具返回结果。
5. 全程使用简体中文。
6. 每个步骤完成后，核对产出文件是否存在、内容是否正确。

## 执行步骤
### 步骤 1：判断是否已初始化
调用 impm_isinit(projectRoot) 判断 docs/project.md 与 docs/sad.md 是否都存在且非空：
- 若两者都存在且非空：项目已初始化，本技能结束，不创建、不修改任何文件，向用户输出判定结论（已初始化，跳过初始化阶段）。
- 否则，继续执行步骤 2。

### 步骤 2：判断项目类型
检查当前项目是否有实质性的编码或项目结构（源代码目录、配置文件、可运行程序等）：
- 没有实质性编码或项目结构：判定为空项目，按空项目初始化——各文档按模板写入空结构。
- 有实质性编码或项目结构：判定为存量项目，按存量项目反推补全——各文档根据现有代码与文档反推内容。

### 步骤 3：输出判定结论并记录进度
向用户输出初始化判定结论，包括：是否已初始化、项目类型（空项目/存量项目）、后续初始化方式（按空结构写入/按存量项目反推补全）。调用 impm_progress(projectRoot, {项目英文缩写}, {当前版本号}, add, impm-init-isinit, 已完成) 记录本步骤完成；若 version_progress.md 尚不存在（impm-init-version 未执行），跳过进度记录并提示用户，由 impm-init-version 统一补录。

## 交付物
- 初始化判定结论（向用户输出的文本，不产生文件）
