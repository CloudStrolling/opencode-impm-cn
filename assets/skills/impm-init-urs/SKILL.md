# impm-init-urs 技能

## 触发词
- URS
- 用户需求说明书
- 需求文档
- 用户需求

## 何时使用
- 初始化阶段的需求步骤（/impm-init-urs）执行时。
- 需要创建或补全用户需求说明书（URS）时。

## 执行角色
本技能由 业务分析师（subagent_type=ba）subagent 负责执行，执行时使用 Skill 工具加载本技能。

## 调度说明（PM/上级编排者启动本技能时必须遵守）
1. 启动方式：使用 task 工具启动 subagent，subagent_type 必须为 `ba`；禁止由 PM 或编排者自己代替执行本技能内容。
2. 提示词必传上下文（缺一不可）：项目根目录绝对路径（projectRoot）、项目英文缩写（{项目英文缩写}）、当前版本号（{当前版本号}）、用户输入 $ARGUMENTS 原文（含用户提到的文件路径）、技能名（impm-init-urs，要求 subagent 先用 Skill 工具加载本技能再执行）。
3. 完成要求：等待 subagent 返回完成结果后，核对产出文件与 version_progress.md 进度记录，全部正确后才能进入下一步。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文名称 | 项目的英文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接所有文档路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 当前版本号 | 当前执行的版本号（初始化阶段固定为 0.0.1） | 通过 impm_version 获取或从版本目录名推断 |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 只执行本技能规定的操作，不做与任务无关的工作。
3. 所有文档路径必须用 {项目英文缩写} 和 {当前版本号} 拼接，不得臆造文件名。
4. 使用 impm_* 工具获取信息，不得编造工具返回结果。
5. 全程使用简体中文。
6. 每个步骤完成后，核对产出文件是否存在、内容是否正确。

## 执行步骤
### 步骤 1：读取模板
调用 impm_template_reader(projectRoot, URS-TEMPLATE.MD) 读取用户需求说明书模板，明确模板章节：业务目标、用户角色、业务场景、功能需求、非功能需求、约束条件、假设与依赖。

### 步骤 2：反推用户需求
通过 impm_doc_reader 读取已有文档（project、sad 等），结合当前项目代码和文档，按模板格式填写 URS：
- 存量项目：从现有代码与文档反推各章节内容（业务目标、用户角色、业务场景、功能需求、非功能需求、约束条件、假设与依赖）。
- 空项目：按模板结构写入空文档，章节标题保留，内容填写"待补充"或空值。
- 需求编号规则：功能需求（FR）、非功能需求（NFR）编号项目全局唯一，格式为「前缀-v版本号-序号」（如 FR-v0.0.1-001、NFR-v0.0.1-001），序号在所属版本内从 001 顺序递增；跨版本保持不变的需求沿用原编号。

### 步骤 3：写入版本文档并提取摘要写入主文档
1. 调用 impm_doc_writer(projectRoot, urs, {项目中文名称}, {当前版本号}, {任务编号}, version, 完整内容)：写入完整版本文档 docs/{项目英文缩写}-v0.0.1/{项目英文缩写}-urs-v0.0.1.md。
2. 从当前版本 URS 中提取摘要（摘要格式见下），调用 impm_doc_writer(projectRoot, urs, {项目中文名称}, {当前版本号}, {任务编号}, main, 摘要内容)：写入主文档 docs/{项目英文缩写}-urs.md（不存在则创建）。主文档只写摘要，不复制完整内容。
3. 核对版本文档为完整内容、主文档为摘要内容，两个文件均存在。

#### URS 摘要格式（写入主文档）
- 文档头：项目名称、汇总说明、版本演进表（版本号 / 日期 / 变更摘要 / 关联完整文档路径）、完整文档索引（各版本完整 URS 文件路径清单）。
- 一、需求清单：| 分组 | 需求编号 | 需求名称 | 需求描述（一行摘要） | 优先级 | 来源版本 |，按「项目 → 模块 → 业务场景」重组并按业务逻辑排序（主流程在前、支线在后），后续版本合并时插入到所属业务逻辑位置，编号全局唯一不重复。
- 二、非功能需求清单：| 编号 | 类别 | 需求描述（一行摘要） | 指标 | 来源版本 |，按类别（性能/安全/可用性等）分组排序。
- 三、业务目标：按业务线/目标主题分组概要，不按版本分节。
- 四、约束条件与假设依赖：按主题分类概要条目，不按版本分节。
- 正文不按版本号分节；版本信息统一由「来源版本」列与版本演进表承载。
- 尾部注明：完整内容见版本目录 docs/{项目英文缩写}-v0.0.1/{项目英文缩写}-urs-v0.0.1.md。

### 步骤 4：记录进度
调用 impm_progress(projectRoot, {项目英文缩写}, {当前版本号}, add, impm-init-urs, 已完成) 记录本步骤完成。

## 交付物
- docs/{项目英文缩写}-v0.0.1/{项目英文缩写}-urs-v0.0.1.md（完整用户需求说明书）
- docs/{项目英文缩写}-urs.md（需求摘要汇总，非完整内容）
