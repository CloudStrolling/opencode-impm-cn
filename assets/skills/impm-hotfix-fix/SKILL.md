# impm-hotfix-fix 技能

## 触发词
- 修复 bug
- 热修复编码
- 修复代码
- hotfix-fix

## 何时使用
impm-hotfix 编排技能（环节2）完成 bug 定位分析后，需要按根因分析与修复方案快速修复代码时使用。本技能为热修复流程专用，跳过全部前置文档环节，追求最小改动与最快修复。

## 执行角色
本技能由 sse、fee、bee subagent 负责执行，执行时使用 Skill 工具加载本技能。调度方（impm-hotfix）按 bug 性质选择对应角色：前端页面类 bug→fee、后端接口/逻辑类 bug→bee、通用类 bug→sse。

## 调度说明（PM/impm-hotfix 启动本技能时必须遵守）
1. 启动方式：使用 task 工具启动 subagent，subagent_type 按 bug 性质决定：`fee`（前端页面类）、`bee`（后端接口/逻辑类）、`sse`（通用类）；禁止由调度方自己代替执行本技能内容。
2. 提示词必传上下文（缺一不可）：项目根目录绝对路径（projectRoot）、项目英文缩写（{项目英文缩写}）、用户输入 $ARGUMENTS 原文（含 bug 描述与相关文件路径）、技能名（impm-hotfix-fix，要求 subagent 先用 Skill 工具加载本技能再执行）、根因分析、修复方案。
3. 完成要求：等待 subagent 返回完成结果后，核对改动文件与验证结果，全部正确后才能进入下一步。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文名称 | 项目的英文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接文档路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 根因分析 | 调度方定位到的 bug 根因 | 由调度方（PM）传入 |
| 修复方案 | 调度方确定的修复方案 | 由调度方（PM）传入 |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 只执行本技能规定的操作，不做与任务无关的工作。
3. 使用 impm_* 工具获取信息，不得编造工具返回结果。
4. 全程使用简体中文。
5. 本技能为热修复流程的一部分，只能被 impm-hotfix 调度执行，不能单独执行。

## 执行步骤
### 步骤 1：接收根因与修复方案
接收调度方传入的根因分析、修复方案与相关文件路径，确认修复目标与边界（本次只修 bug，不做需求扩展）。

### 步骤 2：阅读相关代码
用 read/grep/glob 工具读取相关代码文件（含 bug 现场文件、调用链上相关文件、相关配置文件），核实根因分析是否正确；若发现根因分析有误，向调度方说明并建议修正。

### 步骤 3：修复代码
按修复方案修改代码，力求最小改动、不引入副作用、不改变无关行为；修复时注意异常处理、边界条件与兼容性（不破坏既有功能）。

### 步骤 4：验证修复
1. 若项目有现有测试框架：补充针对该 bug 的回归测试用例（覆盖触发条件与期望行为），运行相关测试确认通过；再运行该模块相关既有测试确认无回归。
2. 若项目无测试框架：手动验证 bug 场景（运行程序/脚本复现修复前后行为），确认修复生效。
3. 检查改动是否影响其他调用方（用 grep 查找相关引用），必要时补充验证。

### 步骤 5：返回结果
向调度方返回：改动文件路径清单、修复逻辑说明、验证结果（测试通过情况/手动验证结论）、遗留风险（如有）。

## 交付物
- 修复后的代码文件与回归测试
- 验证结果说明（返回给调度方）

## 完成后提示
- 本步骤完成后，由调度方（impm-hotfix）按流程继续执行下一步骤（留存提交）。
