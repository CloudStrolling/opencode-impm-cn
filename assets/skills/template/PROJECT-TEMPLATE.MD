# 编码规范
## 文件组织规范
- 按功能模块组织目录，公共代码放公共目录，避免循环依赖。
## 命名规范
- 文件、目录、类、函数、变量的命名遵循所用语言的社区约定。
## 代码风格
- 遵循所用语言的主流代码风格（缩进、引号、换行、分号）。
## 注释规范
- 关键类、函数、复杂逻辑必须有简体中文注释；注释说明"为什么"而非"是什么"。
## 日志规范
- 统一日志级别（DEBUG/INFO/WARN/ERROR），关键业务路径必须记录日志，禁止输出敏感信息。
## 测试规范
- 测试先行（TDD）：编码前先写测试用例，编码后测试必须全部通过。
## 统一错误处理规范
- 统一错误码与错误信息格式，接口层统一封装错误响应，禁止吞异常。
## 其他规范
- 禁止提交密钥、密码、环境变量等敏感信息；不提交日志与临时文件。
