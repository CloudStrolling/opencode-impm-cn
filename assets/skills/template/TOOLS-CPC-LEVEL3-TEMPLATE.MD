# 等保三级代码审查 Checklist
**项目名称**：**检查日期**：**检查人**：TL **标准依据**：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第三级安全要求

## 使用说明
1. 本 Checklist 从 GB/T 22239-2019 第三级安全要求中梳理出与软件开发直接相关的条款，供代码审查时逐项核查。
2. 每个检查项的检查结果只能取三种取值：
   - 通过：有代码、配置或文档证据表明满足要求；
   - 不通过：发现不符合项或未找到证据，必须在说明中写明具体不通过原因（涉及文件位置与问题描述）；
   - 不适用：当前项目确实不存在该场景（如无外包开发、不采集个人信息），必须在说明中写明理由。
3. 检查证据需给出文件路径（含行号）、配置位置或文档名称。

## 2. 开发过程管理

## 3. 身份鉴别与会话管理
### 对应标准：安全计算环境 8.1.4.1
| 编号 | 标准条款 | 检查要点 | 检查结果 | 说明（证据位置/不通过原因） |
| --- | --- | --- | --- | --- |
| AUTH-01 | 应对登录的用户进行身份标识和鉴别，身份标识具有唯一性，身份鉴别信息具有复杂度要求并定期更换 | 用户唯一标识；口令复杂度校验与定期更换策略；禁止空口令、弱口令 |  |  |
| AUTH-02 | 应具有登录失败处理功能，可采取结束会话、限制非法登录次数和当登录连接超时自动退出等措施 | 登录失败锁定/限制次数；会话超时自动退出配置 |  |  |
| AUTH-03 | 应采用两种或两种以上组合的鉴别技术对用户进行身份鉴别，且其中一种鉴别技术至少应使用密码技术来实现 | 双因素认证（如口令+短信/邮箱验证码/OAuth/MFA），至少对系统管理用户启用 |  |  |
| AUTH-04 | 应采取必要措施防止鉴别信息在网络传输过程中被窃听 | 鉴别信息通过 HTTPS/TLS 加密传输；禁止明文 HTTP 传输口令 |  |  |

## 4. 访问控制
### 对应标准：安全计算环境 8.1.4.2
| 编号 | 标准条款 | 检查要点 | 检查结果 | 说明（证据位置/不通过原因） |
| --- | --- | --- | --- | --- |
| ACL-01 | 应对登录的用户分配账户和权限 | 有账户与权限管理体系（RBAC 等），权限分配有依据 |  |  |
| ACL-02 | 应重命名或删除默认账户，修改默认账户的默认口令 | 无默认弱口令账户；无硬编码账户/后门账号 |  |  |

| ACL-04 | 应授予管理用户所需的最小权限，实现管理用户的权限分离 | 最小权限原则；管理与业务操作权限分离（如系统管理员与审计员分立） |  |  |
| ACL-05 | 应由授权主体配置访问控制策略，访问控制的粒度达到主体为用户级或进程级、客体为文件或数据库表级 | 服务端强制鉴权；防止水平越权和垂直越权；关键资源访问粒度到用户级/表级 |  |  |

## 5. 安全审计
### 对应标准：安全计算环境 8.1.4.3
| 编号 | 标准条款 | 检查要点 | 检查结果 | 说明（证据位置/不通过原因） |
| --- | --- | --- | --- | --- |
| AUD-01 | 应启用安全审计功能，审计覆盖到每个用户，对重要的用户行为和重要安全事件进行审计 | 登录/登出、授权变更、关键业务操作等重要事件均有留痕 |  |  |
| AUD-02 | 审计记录应包括事件的日期和时间、用户、事件类型、事件是否成功及其他与审计相关的信息 | 日志字段完整（时间、用户、事件类型、结果等） |  |  |
| AUD-03 | 应对审计记录进行保护，定期备份，避免受到未预期的删除、修改或覆盖等 | 审计日志防篡改（只追加、访问控制）；日志中不记录明文敏感信息；有备份策略 |  |  |
| AUD-04 | 应对审计进程进行保护，防止未经授权的中断 | 日志/审计进程不可被普通用户随意停用；异常中断有告警 |  |  |

## 6. 入侵防范与输入安全
### 对应标准：安全计算环境 8.1.4.4
| 编号 | 标准条款 | 检查要点 | 检查结果 | 说明（证据位置/不通过原因） |
| --- | --- | --- | --- | --- |
| SEC-01 | 应提供数据有效性检验功能，保证通过人机接口输入或通过通信接口输入的内容符合系统设定要求 | 所有外部输入（HTTP 参数、API 报文、文件上传等）均有服务端校验 |  |  |
| SEC-02 | 应防范注入类攻击（SQL 注入、XSS、命令注入、路径穿越、反序列化、SSRF 等，属数据有效性检验与安全编码范畴） | 参数化查询、输出编码、白名单校验等防护措施到位 |  |  |
| SEC-03 | 应能发现可能存在的已知漏洞，并在经过修补或采取其他补救措施后方可重新上线 | 第三方依赖无高危已知漏洞；有依赖漏洞扫描（npm audit/pip-audit/OWASP 扫描等）与修补记录 |  |  |
| SEC-04 | 错误信息安全（测评实践）：不应向客户端返回堆栈、SQL 语句、物理路径等敏感信息 | 全局异常处理；生产环境关闭调试模式与详细错误输出 |  |  |
| SEC-05 | 应遵循最小安装的原则，仅安装需要的组件和应用程序；关闭不需要的服务和高危端口 | 仅启用必要组件、服务和端口；关闭调试接口与管理后门 |  |  |

## 7. 数据安全
### 对应标准：安全计算环境 8.1.4.7～8.1.4.10
| 编号 | 标准条款 | 检查要点 | 检查结果 | 说明（证据位置/不通过原因） |
| --- | --- | --- | --- | --- |
| DAT-01 | 应采用校验技术或密码技术保证重要数据在传输过程中的完整性（鉴别数据、重要业务数据、重要审计数据、重要配置数据等） | 重要数据传输有完整性校验（签名/HMAC/TLS） |  |  |
| DAT-02 | 应采用校验技术或密码技术保证重要数据在存储过程中的完整性 | 重要数据存储有完整性保护（校验和/签名/数据库约束） |  |  |
| DAT-03 | 应采用密码技术保证重要数据在传输过程中的保密性（鉴别数据、重要业务数据和重要个人信息等） | 敏感数据传输全程加密（TLS）；内部服务间调用亦不裸奔明文 |  |  |
| DAT-04 | 应采用密码技术保证重要数据在存储过程中的保密性 | 口令加盐慢哈希存储；敏感字段加密存储；密钥不硬编码、不入库 |  |  |
| DAT-05 | 应提供重要数据的本地数据备份与恢复功能；提供异地实时备份功能（适用时）；提供重要数据处理系统的热冗余，保证系统的高可用性 | 有备份/恢复机制（定时备份脚本、快照、主从热备等） |  |  |
| DAT-06 | 应保证鉴别信息所在的存储空间被释放或重新分配前得到完全清除；存有敏感数据的存储空间被释放或重新分配前得到完全清除 | 内存/缓存/临时文件中的口令、Token、敏感数据在使用后及时清除，不长期残留 |  |  |
