# impm-task-coding-run-unit-test 技能

## 触发词
- 执行测试
- 运行测试
- run-unit-test

## 何时使用
当前任务的测试函数编写完成后，需要执行单元测试、确认测试结果并更新文档时使用。

## 执行角色
本技能由 测试工程师（subagent_type=te）subagent 负责执行，执行时使用 Skill 工具加载本技能。

## 调度说明（PM/上级编排者启动本技能时必须遵守）
1. 启动方式：使用 task 工具启动 subagent，subagent_type 必须为 `te`；禁止由 PM 或编排者自己代替执行本技能内容。
2. 提示词必传上下文（缺一不可）：项目根目录绝对路径（projectRoot）、项目英文缩写（{项目英文缩写}）、当前版本号（{当前版本号}）、用户输入 $ARGUMENTS 原文（含用户提到的文件路径）、技能名（impm-task-coding-run-unit-test，要求 subagent 先用 Skill 工具加载本技能再执行）、任务编号（taskId，从 $ARGUMENTS 提取，缺失时用 impm_task_manager 查询下一个可执行任务）。
3. 完成要求：等待 subagent 返回完成结果后，核对产出文件与 version_progress.md 进度记录，全部正确后才能进入下一步。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文名称 | 项目的英文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接所有文档路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 当前版本号 | 当前执行的版本号 | 通过 impm_version action=current 获取，或从版本目录名推断 |
| 任务编号 | 当前执行的任务编号（如 TASK-001） | 由调度方（PM/上级技能）传入 |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 只执行本技能规定的操作，不做与任务无关的工作。
3. 所有文档路径必须用 {项目英文缩写}、{当前版本号}、{任务编号} 拼接，不得臆造文件名。
4. 使用 impm_* 工具获取信息，不得编造工具返回结果。
5. 全程使用简体中文。
6. 每个步骤完成后，核对产出文件是否存在、内容是否正确。
7. 本技能为编码流程的一部分，只能被 impm-task-coding 或 impm-coding 调度执行，不能单独脱离版本号和任务编号执行。

## 执行步骤
### 步骤 1：接收版本号与任务编号
接收调度方传入的当前版本号与任务编号（{任务编号}，如 TASK-001）。

### 步骤 2：读取测试用例
调用 impm_doc_reader（docType=testcase，taskId={任务编号}），读取当前任务的测试用例中的单元测试部分。

### 步骤 3：执行单元测试
找到本任务编写的单元测试函数，使用当前开发语言或构建环境中的单元测试工具（如 pytest / go test / mvn test / npm test / dotnet test 等）执行单元测试。

执行完成后生成单元测试结果概览（通过/失败用例数与失败原因）。

### 步骤 4：处理失败的单元测试
如果单元测试有失败用例，对每个失败用例逐一分析判定：

1. **判定测试是否过时或非必须**：
   - **过时判定**：测试对应的被测函数/方法已不存在、被重命名、或接口签名已变更，导致测试无法匹配当前代码；
   - **非必须判定**：测试覆盖的业务逻辑已废弃、功能已移除、或该测试对当前版本无实际验证价值。

2. **过时或非必须的处理**：
   - 删除该测试用例的测试函数代码；
   - 同步更新当前任务的 testcase.md，删除该用例对应的测试用例记录；
   - 删除后重新执行剩余单元测试，确认无新失败产生。

3. **必须的测试处理**：
   - 针对失败原因，修改被测代码（impm-task-coding-code）修复缺陷；
   - 修复后重新执行单元测试，验证该用例通过；
   - 连续失败达上限（3次）则中止本任务并向用户报告该用例失败详情。

### 步骤 5：更新测试结果
所有单元测试执行完成后：
1. 更新当前任务的测试用例的测试通过情况（更新任务目录 testcase.md，标注通过/失败及失败原因）。
2. 将单元测试结果写入任务目录 {任务编号}/unit-test-result.md（参考 UNIT-TEST-RESULT-TEMPLATE.MD 模板格式），文件已存在则覆盖，保证当前文件为最新。内容包括：
   - **测试结果概览**：用例总数、通过数、失败数、跳过数、通过率、测试时间、运行环境、执行命令；
   - **每个单元测试的执行结果明细**：用例编号、用例名称、执行结果（通过/失败/跳过）、失败原因（如有）；
   - **过时/非必须用例删除记录**（如有）。

### 步骤 6：确认全部通过
如果全部单元测试都成功（或失败用例已按步骤 4 处理完毕），表明当前任务单元测试已通过。

### 步骤 7：记录完成
调用 impm_progress（action=add，stepName=impm-task-coding-run-unit-test，status={任务编号}-已完成）。

## 交付物
- 任务目录 testcase.md（已更新测试通过情况）
- 任务目录 unit-test-result.md（单元测试结果概览与执行明细）
- version_progress.md 中的进度记录

## 完成后提示
- 本技能全部操作完成后必须立即结束并返回调度方：产出文件路径清单与 version_progress.md 中本技能的进度状态；严禁自行继续执行后续阶段或后续任务、严禁等待后续指令，后续调度由调度方（PM）负责。
