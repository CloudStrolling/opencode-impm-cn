# impm-doc-merge 技能

## 触发词
文档合并、合并主文档、doc-merge、版本文档合并

## 何时使用
阶段4中，项目地图更新完成后，需要将当前版本的各设计文档合并到 docs 下对应的主文档时使用。

## 执行角色
本技能由 文档编写（subagent_type=dw）subagent 负责执行，执行时使用 Skill 工具加载本技能。

## 调度说明（PM/上级编排者启动本技能时必须遵守）
1. 启动方式：使用 task 工具启动 subagent，subagent_type 必须为 `dw`；禁止由 PM 或编排者自己代替执行本技能内容。
2. 提示词必传上下文（缺一不可）：项目根目录绝对路径（projectRoot）、项目英文缩写（{项目英文缩写}）、当前版本号（{当前版本号}）、用户输入 $ARGUMENTS 原文（含用户提到的文件路径）、技能名（impm-doc-merge，要求 subagent 先用 Skill 工具加载本技能再执行）。
3. 完成要求：等待 subagent 返回完成结果后，核对产出文件与 version_progress.md 进度记录，全部正确后才能进入下一步。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文名称 | 项目的英文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接所有文档路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 当前版本号 | 当前执行的版本号 | 通过 impm_version action=current 获取，或从版本目录名推断 |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 只执行本技能规定的操作，不做与任务无关的工作。
3. 所有文档路径必须用 {项目英文缩写} 和 {当前版本号} 拼接，不得臆造文件名。
4. 使用 impm_* 工具获取信息，不得编造工具返回结果。
5. 全程使用简体中文。
6. 每个步骤完成后，核对产出文件是否存在、内容是否正确。

## 执行步骤

### 合并总原则（重构式合并）
本技能执行「重构式合并」而非简单追加：主文档按**项目组织方式 → 代码结构 → 系统架构**组织章节，当前版本内容合并进既有结构中，而不是在文档末尾追加"本版本内容"大段。

1. **载入结构基准**：先用 impm_doc_reader 读取 docs/project.md（项目地图、目录组织）与 docs/{项目英文缩写}-sad.md（系统架构：模块划分、分层、部署形态），作为主文档的章节组织依据；两者缺失时以 LLD 的模块划分为基准。
2. **结构导向、原位更新**：已存在的同名章节/条目原位更新，不重复出现；新出现的模块/表/接口分组插入到与架构一致的位置，随架构演进（重构）调整主文档章节顺序，始终与当前系统结构一致。
3. **增量合并、版本溯源**：长期存续的条目（接口、表、模块、需求编号）标注"来源版本/最近修改版本"；变更、重命名、下线的条目在文档内统一"变更记录"表留痕，保证可追溯。
4. **文档头版本演进表**：每个主文档顶部维护版本演进表（版本号 / 日期 / 变更摘要 / 关联完整文档路径），本次合并追加当前版本一行。
5. **不覆盖历史**：仅对当前版本涉及的内容做更新/新增/下线处理，主文档中其他历史内容保持不变。
6. **主文档与完整文档分工**：URS、PRD 主文档只承载**摘要**，且正文**不按版本号分节**，按「项目 → 模块 → 业务逻辑」重组并逻辑排序（版本信息由来源版本列/版本演进表承载）；完整表述保留在版本目录文档中。API、DBD、LLD 主文档承载**完整设计**（因这部分内容以当前系统结构为权威，不随版本堆积）。

### 步骤 0：准备
1. 读取 docs/project.md 与 docs/{项目英文缩写}-sad.md，确定模块划分与结构基准。
2. 汇总待合并文件清单，逐文件确认主文档是否存在（不存在则后续步骤创建）。

### 步骤 1：合并 URS 文档（摘要式 + 按业务逻辑重组）
1. 用 impm_doc_reader（docType=urs，target=main）读取主文档 docs/{项目英文缩写}-urs.md；若不存在按摘要模板创建。
2. 从版本文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-urs-v{当前版本号}.md 提取摘要：各功能需求（FR-v{版本号}-xxx）的编号/名称/一行描述/优先级/业务归属（所属模块或业务场景），非功能需求（NFR）同样处理，以及业务目标、场景、约束、假设的按主题概要。
3. 将摘要重组并入主文档，**不按版本分节**：已有编号原位更新描述与优先级；新编号按「项目 → 模块 → 业务场景」插入到所属业务逻辑位置并逻辑排序（主流程在前、支线在后）；模块/业务逻辑结构发生变化时，重构主文档的分组与排序以匹配当前业务逻辑；每个条目保留「来源版本」列；业务目标、场景、约束、假设按主题归并到对应章节概要；版本演进表追加当前版本行；完整文档索引追加当前版本文件路径。
4. 尾部注明当前版本完整内容见 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-urs-v{当前版本号}.md。
5. 用 impm_doc_writer（docType=urs，target=main）写回主文档。
6. 核对：主文档为全局需求摘要、按项目/模块/业务逻辑重组排序、无版本号分节，需求编号全局唯一不重复，历史内容保留。

### 步骤 2：合并 PRD 文档（摘要式 + 按模块/业务逻辑重组）
1. 用 impm_doc_reader（docType=prd，target=main）读取主文档 docs/{项目英文缩写}-prd.md；若不存在按摘要模板创建。
2. 从版本文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-prd-v{当前版本号}.md 提取摘要：功能清单（F-v{版本号}-xxx）编号/名称/所属模块/优先级/版本范围，用户故事（US-v{版本号}-xxx）编号/标题/一句话摘要/优先级/所属功能，产品背景/目标用户/数据需求/验收标准按主题概要，版本规划表更新。
3. 将摘要重组并入主文档，**不按版本分节**：已有编号原位更新；新编号按「项目 → 模块」插入到所属模块，模块内按业务逻辑排序（主流程在前、支线在后）；新增模块按业务逻辑插入对应位置；每个功能条目保留「版本范围」，每个用户故事保留「来源版本」列；产品背景/目标用户/数据需求/验收标准按业务主题归并概要；版本演进表追加当前版本行；完整文档索引追加当前版本文件路径。
4. 尾部注明当前版本完整内容见版本目录对应文件。
5. 用 impm_doc_writer（docType=prd，target=main）写回主文档。
6. 核对：主文档为全局产品需求摘要、按项目/模块/业务逻辑重组排序、无版本号分节，编号全局唯一不重复，历史内容保留。

### 步骤 3：合并 API 文档（重构式合并）
1. 用 impm_doc_reader（docType=api，target=main）读取主文档 docs/{项目英文缩写}-api.md；若主文档不存在且当前版本 API 文档存在，按其结构+架构基准创建。
2. 确定接口分组：以 sad.md/LLD 的模块划分为准；现有分组保留，新模块接口插入与架构一致的位置。
3. 将版本文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-api-v{当前版本号}.md 的接口逐条并入：新增接口插入所属模块组；已有接口（URL/路径相同视为同一接口）原位更新请求/响应/错误码，并标注最近修改版本；接口清单同步更新；被删除或废弃的接口移入"废弃/下线接口"小节并标注下线版本。
4. 若本次为首次合并（v0.0.1），按架构分组建立主文档结构，将版本接口重构组织进去而非原文照抄。
5. 用 impm_doc_writer（docType=api，target=main）写回主文档。
6. 核对：主文档按模块分组、无重复定义、接口与编号/来源版本可追溯，历史接口保留。

### 步骤 4：合并 DBD 文档（重构式合并）
1. 用 impm_doc_reader（docType=dbd，target=main）读取主文档 docs/{项目英文缩写}-dbd.md。
2. 将版本文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-dbd-v{当前版本号}.md 的表/索引/视图等按业务域或模块重构并入：新表插入所属业务域；已有表（同名）原位更新字段/索引并标注变更版本；废弃表移入"废弃表"小节；ER 图、数据字典同步更新。
3. 用 impm_doc_writer（docType=dbd，target=main）写回主文档。
4. 核对：主文档按业务域组织、无重复表定义、历史结构保留且与当前版本结构一致。

### 步骤 5：合并 DBD SQL 脚本（重构式合并）
1. 用 impm_doc_reader（docType=sql，target=main）读取主文档 docs/{项目英文缩写}-dbd.sql；若主文档不存在则按版本 SQL 结构创建。
2. 将版本 SQL docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-dbd-v{当前版本号}.sql 并入：新表追加 CREATE TABLE；已存在表生成 ALTER 语句或更新原始 CREATE（保持脚本能从头完整执行）；为每段语句标注来源版本注释；去除重复定义、调整执行顺序（先表后外键/索引）。
3. 用 impm_doc_writer（docType=sql，target=main）写回主文档。
4. 核对：SQL 语句完整、按结构组织、无重复冲突、可直接执行。

### 步骤 6：合并 LLD 文档（重构式合并）
1. 用 impm_doc_reader（docType=lld，target=main）读取主文档 docs/{项目英文缩写}-lld.md。
2. 将版本文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-lld-v{当前版本号}.md 按模块/业务流程并入：新模块插入与架构一致的位置；已有模块的业务规则、时序图、核心逻辑原位更新并标注修订版本；若架构演进导致模块重划，重构主文档章节以匹配当前架构；LLD 中引用的需求/用户故事编号（FR-v{版本号}-xxx、US-v{版本号}-xxx）保持全局唯一一致。
3. 用 impm_doc_writer（docType=lld，target=main）写回主文档。
4. 核对：主文档按模块组织、历史内容保留、与当前系统架构一致、可追溯版本。

### 步骤 7：记录进度
1. 调用 impm_progress add（impm-doc-merge，已完成），在 version_progress.md 中记录本技能完成状态。
2. 核对 version_progress.md 中已记录本步骤状态。

## 交付物
- docs/{项目英文缩写}-urs.md、docs/{项目英文缩写}-prd.md（需求/功能/用户故事**摘要**汇总主文档，非完整内容）
- docs/{项目英文缩写}-api.md、docs/{项目英文缩写}-dbd.md、docs/{项目英文缩写}-dbd.sql、docs/{项目英文缩写}-lld.md（按项目组织方式、代码结构、系统架构**重构式合并**后的完整设计主文档）
- version_progress.md 进度记录

## 完成后提示
- 如需继续执行下一步骤，请输入 /impm-doc-update
- 如需继续执行本阶段后续所有步骤，请输入 /impm-finish
