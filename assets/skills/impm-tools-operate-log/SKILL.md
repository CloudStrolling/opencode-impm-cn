# impm-tools-operate-log 技能

## 触发词
审计日志、操作审计、audit log、operate-log、安全审计埋点、等保审计、tools-operate-log

## 何时使用
需要对当前项目进行操作审计日志埋点检查，验证关键操作（登录/登出、权限变更、数据导出、敏感配置变更、业务关键操作、异常安全事件）是否已实现审计日志记录，且日志字段完整、防护措施到位，并输出检查报告时使用。可独立执行，也可在阶段4代码审核后追加执行。

## 执行角色
本技能由 技术负责人（subagent_type=tl）subagent 负责执行，执行时使用 Skill 工具加载本技能。

## 调度说明（PM/上级编排者启动本技能时必须遵守）
1. 启动方式：使用 task 工具启动 subagent，subagent_type 必须为 `tl`；禁止由 PM 或编排者自己代替执行本技能内容。
2. 提示词必传上下文（缺一不可）：项目根目录绝对路径（projectRoot）、用户输入 $ARGUMENTS 原文（含用户提到的文件路径）、技能名（impm-tools-operate-log，要求 subagent 先用 Skill 工具加载本技能再执行）。
3. 完成要求：等待 subagent 返回完成结果后，核对检查报告产出文件已生成且内容完整，全部正确后才能结束。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接报告路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 检查报告模板 | 操作审计日志埋点检查报告模板 | 通过 impm_template_reader 读取 TOOLS-OPERATE-LOG-TEMPLATE.MD |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 本技能以只读检查为主：除写入检查报告外，不得修改任何代码、配置与其他文档。
3. 检查结果只能取三种取值：通过、不通过、不适用；每项判定必须有实际证据，禁止臆测或编造证据。
4. 判定为不通过的检查项，必须在说明中写明具体不通过原因（涉及文件路径与问题描述）；判定为不适用的检查项，必须在说明中写明理由。
5. 所有文档路径必须用 {项目英文缩写} 拼接，不得臆造文件名。
6. 使用 impm_* 工具获取信息，不得编造工具返回结果。
7. 全程使用简体中文。

## 执行步骤
### 步骤 1：获取项目信息与确定检查范围
1. 调用 impm_project_info 读取 docs/project.md，获得项目中文名称与项目英文缩写；若 docs/project.md 不存在（项目未初始化），终止本技能并提示先执行 /impm-init 完成初始化。
2. 结合 docs/project.md 的项目地图与源代码目录结构，确定本次检查范围：源码目录、日志框架配置文件、中间件/拦截器代码、日志切面配置与 docs 下的设计文档。

### 步骤 2：读取检查报告模板
1. 调用 impm_template_reader（templateName=TOOLS-OPERATE-LOG-TEMPLATE.MD）读取模板全文，获得全部检查项及其检查要点。

### 步骤 3：逐项核查审计日志埋点
1. 按模板中的检查项顺序逐项核查，覆盖全部七大类：用户认证审计、权限变更审计、数据导出审计、敏感配置变更审计、业务关键操作审计、异常与安全事件审计、审计日志防护与运维；不允许跳过任何检查项。
2. 每项必须基于实际证据判定：使用 Glob、Grep、Read 检索代码、配置、日志框架配置、拦截器/切面实现；必要时可运行只读命令辅助确认（如日志框架初始化配置），但不得修改任何文件。
3. 判定规则：
   - 有明确的代码、配置或文档证据表明该操作场景已实现审计日志记录，且日志字段完整、防护措施到位 → 检查结果填「通过」，说明中写明证据位置（文件路径:行号 或 配置位置）；
   - 未找到审计日志埋点证据，或日志字段不完整、防护措施缺失 → 检查结果填「不通过」，说明中写明具体不通过原因（缺失了什么埋点、在哪个文件存在什么问题）；
   - 当前项目确实不存在该操作场景（如无数据导出功能、无敏感配置变更接口）→ 检查结果填「不适用」，说明中写明判定理由。

### 步骤 4：生成检查报告
1. 严格按 TOOLS-OPERATE-LOG-TEMPLATE.MD 的格式组织检查报告：表头信息（项目名称、检查日期、检查人=TL、标准依据）、各类别汇总统计表（检查项数、通过、不通过、不适用数量）、Checklist 明细（每个检查项的检查结果与说明）、总体结论、整改建议优先级。
2. 使用 Write 工具将报告写入 docs/{项目英文缩写}-operate-log-check.md。
3. 核对文件存在且内容完整：每个检查项均填写了检查结果与说明，汇总统计与明细一致。

## 交付物
- docs/{项目英文缩写}-operate-log-check.md（操作审计日志埋点检查报告）

## 完成后提示
- 本技能全部操作完成后必须立即结束并返回调度方（报告路径、检查结论统计与不通过项摘要）；严禁自行继续执行其他技能。
- 若为独立命令运行，向用户汇报报告位置、不通过项摘要与整改建议。
