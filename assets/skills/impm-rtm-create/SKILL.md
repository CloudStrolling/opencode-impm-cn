# impm-rtm-create 技能

## 触发词
需求追踪矩阵、RTM、追踪矩阵、需求跟踪、需求追溯、impm-rtm-create

## 何时使用
在任务清单生成完成（impm-task-create 之后）时使用，根据当前版本的 URS（docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-urs-v{当前版本号}.md）、PRD（docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-prd-v{当前版本号}.md）、LLD（docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-lld-v{当前版本号}.md）与任务清单（docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-task-v{当前版本号}.json），建立"需求 → 设计 → 任务"的多对多追踪矩阵，写入 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-rtm-v{当前版本号}.md，并在版本进度文件中记录本步骤。

## 执行角色
本技能由 技术负责人（subagent_type=tl）subagent 负责执行，执行时使用 Skill 工具加载本技能。

## 调度说明（PM/上级编排者启动本技能时必须遵守）
1. 启动方式：使用 task 工具启动 subagent，subagent_type 必须为 `tl`；禁止由 PM 或编排者自己代替执行本技能内容。
2. 提示词必传上下文（缺一不可）：项目根目录绝对路径（projectRoot）、项目英文缩写（{项目英文缩写}）、当前版本号（{当前版本号}）、用户输入 $ARGUMENTS 原文（含用户提到的文件路径）、技能名（impm-rtm-create，要求 subagent 先用 Skill 工具加载本技能再执行）。
3. 完成要求：等待 subagent 返回完成结果后，核对产出文件与 version_progress.md 进度记录，全部正确后才能进入下一步。

## 关键变量定义与取值
| 变量 | 说明 | 获取方式 |
| 项目中文名称 | 项目的中文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文名称 | 项目的英文名称 | 通过 impm_project_info 从 docs/project.md 读取 |
| 项目英文缩写 | 项目的英文缩写，用于拼接所有文档路径 | 通过 impm_project_info 从 docs/project.md 读取 |
| 当前版本号 | 当前执行的版本号 | 通过 impm_version action=current 获取，或从版本目录名推断 |

## 执行要求
1. 严格按照执行步骤中的内容和顺序依次执行：不跳过、不乱序、不并行、不合并任何步骤。
2. 只执行本技能规定的操作，不做与任务无关的工作。
3. 所有文档路径必须用 {项目英文缩写} 和 {当前版本号} 拼接，不得臆造文件名。
4. 使用 impm_* 工具获取信息，不得编造工具返回结果。
5. 全程使用简体中文。
6. 每个步骤完成后，核对产出文件是否存在、内容是否正确。

## 执行步骤

### 步骤 1：读取模板
调用 impm_template_reader 读取模板 RTM-TEMPLATE.MD，明确需求追踪矩阵的章节结构与填写格式（需求/用户故事清单、多对多关联记录、覆盖校验、问题清单）。

### 步骤 2：收集追踪依据
调用 impm_doc_reader 读取：
1. 当前版本 URS 文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-urs-v{当前版本号}.md，提取原始需求编号（FR-xxx、NFR-xxx）及其名称、描述摘要、优先级；
2. 当前版本 PRD 文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-prd-v{当前版本号}.md，提取用户故事编号（US-xxx）及其故事描述；
3. 当前版本 LLD 文档 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-lld-v{当前版本号}.md，提取设计内容（模块划分、核心业务流程、业务规则等，作为设计追踪对象）；
4. 当前版本任务清单 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-task-v{当前版本号}.json，通过 impm_doc_reader（docType=task）或 impm_task_manager（action=query）获取每个任务；提取任务编号（TASK-xxx）、任务名称（title）、userStoryId、apiId，用于核对任务与需求/用户故事的对应关系。

### 步骤 3：建立需求/用户故事全集
汇总步骤 2 收集的原始需求（FR-xxx / NFR-xxx）与 PRD 用户故事（US-xxx），去重后填入模板"一、需求/用户故事清单"章节，形成本版本需求/用户故事全集。记录每个条目的编号、类型（URS需求/PRD用户故事）、名称、描述摘要与优先级。

### 步骤 4：建立多对多追踪矩阵
按模板"二、追踪矩阵"章节，建立以下关联记录（多对多，一条关联即一行，同一个需求/用户故事可能对应多行）：
1. 需求/用户故事 → 设计：结合 LLD 的模块划分、业务流程与核心业务逻辑，为每个需求/用户故事关联其对应的 LLD 设计内容（模块/流程），生成记录，标注覆盖情况（已覆盖/缺失）；
2. 需求/用户故事 → 任务：依据任务清单中每个任务的 userStoryId，将任务与其对应的需求/用户故事关联起来（用户故事 US-xxx 通过 userStoryId 直接关联；原始需求 FR-xxx / NFR-xxx 依据任务描述、 acceptanceCriteria 与需求描述匹配关联；一个任务可关联多个需求/用户故事，一个需求/用户故事也可被多个任务覆盖），生成记录，标注覆盖情况；
3. 为每条记录分配唯一记录ID（RTM-001、RTM-002……）。
调用 impm_doc_writer（docType=rtm，target=version）写入 docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-rtm-v{当前版本号}.md。

### 步骤 5：执行覆盖完整度校验并生成问题清单
按模板"三、覆盖完整度校验"章节，校验每个需求/用户故事是否有设计、是否有任务、是否有测试用例（此阶段测试用例尚未生成，测试覆盖暂标记为"否/缺失"，待 impm-regression-test 阶段关联测试用例后回填）：
- 若某需求/用户故事缺少设计（LLD 无对应模块/流程）或缺少任务（任务清单中无任何任务覆盖），在"问题标注"列标注对应问题；
- 将校验不通过项填入模板"四、问题清单"章节，给出问题描述与处理建议，状态记为"待处理"。
调用 impm_doc_writer（docType=rtm，target=version，expectedBase=步骤 4 写入后的全文）将含校验结果与问题清单的完整 rtm.md 覆盖写回。

### 步骤 6：记录进度
调用 impm_progress（action=add，stepName=impm-rtm-create，status=已完成）在版本进度文件 docs/{项目英文缩写}-v{当前版本号}/version_progress.md 表格第一行插入新行。
核对产出文件存在、内容正确，进度行已记录。

## 交付物
- docs/{项目英文缩写}-v{当前版本号}/{项目英文缩写}-rtm-v{当前版本号}.md（需求追踪矩阵，含需求/用户故事清单、多对多追踪关联记录、覆盖完整度校验与问题清单）
