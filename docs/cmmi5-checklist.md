# CMMI5 开发文档与代码检查清单

> 依据：CMMI-DEV V1.3 / V2.0 模型五级（Optimizing）要求整理。CMMI5 为累积模型，需同时满足 ML2~ML5 全部相关过程域（PA）的要求。
> 适用范围：软件开发过程中各类文档产物与代码产物的总体要求。
> 整理日期：2026-08-26

## 一、需求类文档与管理（REQM 需求管理 / RD 需求开发）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| R-01 | 用户需求说明书（URS）文档化 | 用户需求经调研挖掘后形成书面 URS，覆盖功能与非功能需求（性能、安全、兼容性等），非功能需求可量化 |
| R-02 | 产品需求规格说明书（PRD/SRS）文档化 | 基于 URS 生成产品级需求规格，含功能列表、优先级、数据要求、前置条件与验收准则 |
| R-03 | 需求评审与干系人确认 | URS/PRD 发布前经过评审（同行评审或里程碑评审），客户/用户参与并给出书面确认 |
| R-04 | 需求双向跟踪矩阵（RTM） | 建立"需求 → 设计 → 代码 → 测试用例"的双向跟踪举证，任一需求可追溯到实现与验证证据 |
| R-05 | 需求变更受控管理 | 变更经变更控制委员会（CCB）评估影响后实施；变更后需求文档版本升级并同步更新下游设计与测试 |

## 二、设计类文档（TS 技术解决方案 / PI 产品集成）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| D-01 | 系统架构设计文档（SAD/HLD） | 描述系统分层、模块划分、技术选型及理由，与需求保持一致 |
| D-02 | 详细设计文档（LLD） | 覆盖模块划分、业务流程、核心业务逻辑，粒度足以指导编码 |
| D-03 | 数据库设计文档（DBD）与 SQL 脚本 | 表结构、字段、索引、约束设计完整，SQL 脚本可重复执行 |
| D-04 | 接口设计文档（API/ICD） | 接口定义完整（路径、方法、入参出参、错误码），保证接口兼容性 |
| D-05 | 设计基于需求的推导一致性 | 设计文档可向上追溯至具体需求条目，无无源设计 |

## 三、编码类要求（TS 实现阶段）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| C-01 | 组织级编码规范 | 有书面的编码规范（命名、结构、返回值格式、接口风格等），全员遵循 |
| C-02 | 代码注释要求 | 方法/关键逻辑必须有注释，注释与代码一致，便于维护交接 |
| C-03 | 按设计编码与架构合规 | 代码符合 SAD/LLD 的分层与依赖方向，不绕过已定义接口 |
| C-04 | 安全编码检查 | 无注入风险（SQL/命令/XSS）、越权访问、硬编码密钥、敏感信息泄露 |

## 四、验证与确认（VER 验证 / VAL 确认）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| V-01 | 测试用例先于编码编写并评审 | 依据需求先行设计测试用例（开发用例），覆盖率满足要求 |
| V-02 | 单元测试全量执行 | 单元测试不可选择性跳过，记录执行命令、通过率、失败明细 |
| V-03 | 接口自动化测试 | 接口集成前自测通过（如 Postman），有自动化脚本与准入标准 |
| V-04 | 功能/UI 测试与确认 | 按真实场景验证功能符合用户预期，留存测试记录 |
| V-05 | 回归测试报告 | 版本级回归测试输出正式报告：环境、统计结果、失败明细、结论 |
| V-06 | 代码同行评审（Code Review） | 提交前经同行/技术负责人评审，覆盖安全、性能、质量、架构合规、测试覆盖，问题闭环跟踪 |
| V-07 | 测试缺口识别 | 对未覆盖的关键路径、边界条件、异常路径给出明确提示 |

## 五、配置管理（CM）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| M-01 | 全部工作产物纳入配置管理 | 代码、文档、测试脚本、模板等纳入版本控制工具统一管理 |
| M-02 | 基线管理 | 在关键节点（版本发布、里程碑）建立基线，基线变更受控 |
| M-03 | 提交规范与可追溯性 | 提交必须填写备注（关联任务/缺陷），提交历史可追溯 |
| M-04 | 合并与集成控制 | 分支合并策略明确（如 squash merge），合并前工作区核对干净 |
| M-05 | 并发修改冲突控制 | 多任务并行时的共享产物写入有冲突检测与恢复机制 |

## 六、质量保证（PPQA）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| Q-01 | 过程符合性检查 | 独立 QA 依检查单对各过程活动进行客观审计，产出留痕 |
| Q-02 | 产品质量审核 | 对工作产物（文档/代码）进行符合性审核，出具审核报告 |
| Q-03 | 不符合项闭环跟踪 | 不符合项记录、指派、修复状态标注，未修复项说明原因并向管理层汇报 |

## 七、项目策划与监控（PP 项目策划 / PMC 项目监控）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| P-01 | 任务分解与依赖排序（WBS） | 工作分解到任务级，明确上下游依赖与完成标准 |
| P-02 | 进度状态记录与跟踪 | 各步骤/任务状态实时记录，里程碑达成情况可视 |
| P-03 | 偏差纠正机制 | 失败/偏差时定位原因、重试或上报，重试次数有上限 |
| P-04 | 异常监控与告警 | 执行异常（卡死/中断）有监控告警与自动恢复手段 |

## 八、度量与分析（MA）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| A-01 | 过程度量数据采集与存储 | 采集进度、工作量、耗时等过程数据并持久化存储 |
| A-02 | 质量/缺陷度量与分析 | 度量缺陷密度、缺陷移除率（DRE）、测试覆盖率、泄露率等质量指标，定期分析并交流结果 |

## 九、量化管理与统计控制（OPP 组织过程性能 / QPM 量化项目管理）— ML4/ML5 核心

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| N-01 | 组织级过程性能基线（PPB） | 基于历史项目数据建立关键度量项（缺陷密度、生产率等）的均值与上下限基线 |
| N-02 | 组织级过程性能模型（PPM） | 建立可预测的性能模型 y=f(x)，支持在项目中预测目标达成情况 |
| N-03 | 项目量化目标与子过程统计控制 | 项目建立质量与过程性能目标，选定关键子过程用统计方法（SPC 控制图等）监控偏差并纠正 |

## 十、原因分析与持续改进（CAR 原因分析与解决 / OPM/OID 组织绩效管理与革新部署）— ML5 核心

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| I-01 | 缺陷根因分析（CAR） | 对选出的缺陷系统性分析根本原因（5Why/鱼骨图），实施行动建议并评估效果、记录数据 |
| I-02 | 缺陷预防与经验复用 | 根因结论沉淀为检查单/规范更新，防止同类缺陷再次发生 |
| I-03 | 组织级持续过程改进（OPM/OID） | 基于量化数据选择并部署过程与技术改进措施，度量改进效果 |

## 十一、其他支持类（RSKM / DAR / SAM / OT / OPD / OPF）

| 编号 | 检查项 | 要求说明 |
|----|----|----|
| S-01 | 风险管理（RSKM） | 识别风险、分级、制定缓解计划并跟踪至关闭，维护风险库 |
| S-02 | 决策分析（DAR） | 重大决策（技术选型等）有备选方案评价记录与选择准则 |
| S-03 | 供应商协议管理（SAM） | 外购/外包部分有协议管理与验收 |
| S-04 | 组织培训（OT） | 培训需求识别、计划实施与效果收集 |
| S-05 | 组织级标准过程与过程资产（OPD/OPF） | 组织有定义的标准过程集、文档模板库、历史数据库，并按 OPF 持续改进 |
| S-06 | 知识资产沉淀与复用 | 经验教训、可复用组件入库供后续项目使用 |
