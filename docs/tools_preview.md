## 十三、编排原则

> **别把所有检查都做成"阻塞式硬门禁"。** DevSecOps 最佳实践：只有"密钥泄露、未签名制品、严重策略违规"做硬 block；其余（复杂度偏高、覆盖率不足、技术债务）做"软门禁 + 路由到人 + SLA 跟进"。否则流程编排插件反而会成为开发者的枷锁，被绕过去或弃用。
